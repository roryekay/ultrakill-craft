# Setup dependency review

Originally checked 2026-10-10; setup integration rechecked 2026-10-17. No suitable popular complete installer for this exact two-game bridge was found. Setup uses the existing vendor runtimes and official metadata, with custom PowerShell glue for this mod's files/profile. Dependency executables are not bundled in the repository. Download URLs and hashes are pinned in `Setup.Dependencies.json`; bundled metadata hashes are in `SHA256SUMS.txt`.

Review covered ReShade's installation/extraction path, solution/build documentation and license; Fabric's profile and metadata paths, Gradle dependencies/build configuration and license; BepInEx's existing loader dependency, release metadata, README dependencies and project manifest; Java/Fabric API release provenance and published hashes. ReShade's locally pinned download hash detects later changes, but is not an independently published vendor signature. Setup downloads and checks all archives before copying installed files; archives are checked for paths escaping their extraction directory. It never runs ReShade's setup executable or third-party installation scripts.

The old live Fabric JSON checksum failed in issue #2. `Minecraft/fabric-version.json` now contains the fixed response from [Fabric's official endpoint](https://meta.fabricmc.net/v2/versions/loader/26.3/0.19.5/profile/json), retrieved 2026-10-17 and compared with the working Doomcraft Eternal package's reviewed profile. Setup never fetches that changing response. `Minecraft/vanilla-version.json` comes from [Mojang's version metadata](https://piston-meta.mojang.com/v1/packages/11f1aefe473eefba0af62e3286c33b692807b2eb/26.3.json); its SHA1 was checked against the official version manifest (`11f1aefe473eefba0af62e3286c33b692807b2eb`). Both files are public installation metadata, not game binaries/assets, and are covered by the package SHA256 manifest. The official launcher still downloads the owned game, libraries and assets on Play.

No concerning behavior was found in those reviewed setup paths. This is a limited integration review, not a full audit of every loader, JVM or transitive dependency. Existing game/mod compatibility and a completely fresh PC still require real-world testing.

Setup only reads launcher profile configuration, not Minecraft account/credential files. It preserves unrelated profile data and backs up replaced files. The games and official launcher must already be installed and signed in. The launcher handles licensed Minecraft and library downloads on Play. No system Java/PATH changes, telemetry, credentials, proprietary game files or source/development logs are included.

## Verification

Run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-Setup.ps1` from a checkout extracted outside AppData, with the games/launcher closed. Optional `-DownloadCache "<verified downloads folder>"` reuses archives; missing downloads are fetched normally. Tests create isolated fixture folders beside the checkout and leave them for inspection; no installed games or player profiles are modified.

The Windows PowerShell 5.1 fixtures use real hash-verified dependency archives. They cover clean/repeat installation, both launcher profile formats, bundled Fabric/vanilla metadata, installed Java/loaders/mods, retaining unrelated profiles/settings and a world sentinel, retaining unrelated mod config, replaced-file/profile backups, shortcut creation/arguments, the real Setup.cmd preview and failure exit code, a no-write WhatIf preview, profile-folder conflicts, AppData refusal, ZIP traversal rejection before extraction, and corrupt-download rejection without replacing a cached file. Steam auto-detection was checked against an installed Steam library in the original review. No games were launched by these installer tests. A fresh-machine sign-in/Play sequence and gameplay after this installer change were not tested.
